# Support

[English](SUPPORT.md) | [简体中文](SUPPORT.zh.md)

## Where to get help

- **Documentation** — start with the [documentation index](docs/README.md), especially [FAQ](docs/11-faq.md), [Integrators](docs/06-integrators.md), and [Deployment](docs/08-deployment.md).
- **Questions and design discussions** — use GitHub Discussions if enabled, or open an issue with the `question` label.
- **Bug reports** — use the bug report issue template. Include the commit, cluster, program ID, transaction signature, and logs.
- **Feature requests** — use the feature request template. Explain the problem before the solution.
- **Security issues** — follow [SECURITY.md](SECURITY.md). Do not open a public issue.

## What to include

For build or test problems, include:

- Operating system and architecture.
- `rustc --version`, `solana --version`, `anchor --version`, `node --version`, `yarn --version`.
- The command you ran and the full error output.
- Whether you are on `main`, a release tag, or a fork.

For transaction problems, include:

- Cluster and program ID.
- Transaction signature or a reproducible script.
- The instruction and accounts involved.
- Relevant program logs (`solana logs` or the explorer).

## Support scope

This is a community-supported open-source project. Maintainers help on a best-effort basis. There is no SLA and no commercial support contract.

## Contributing a fix

If you can reproduce the issue and know the fix, see [CONTRIBUTING.md](CONTRIBUTING.md) and open a pull request. A minimal reproduction is the fastest path to a fix.

## Code of conduct

All support channels are covered by [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
